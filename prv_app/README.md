# Приложение «Расчёт динамики предохранительного клапана (PRV)»

GUI-приложение, полностью повторяющее математику расчёта из файла
`Another_PRessure_Radau.py` репозитория:

* интегрирование жёсткой ОДУ-системы методом **Radau** (`scipy.solve_ivp`);
* строгая термодинамика азота по **CoolProp (HEOS)** — давление вычисляется
  напрямую из текущих полной массы `M_tot` и внутренней энергии `U_tot`;
* кубические сплайны характеристик клапана (`alpha_c`, `rho_flow`) — как в оригинале;
* динамика золотника: сила давления с коэффициентом `rho_flow(h/d_c)`, пружина
  с автопреднатягом под `P_open`, демпфирование `η`, гравитация, упоры `k_stop/c_stop`;
* истечение через клапан по формуле критического/докритического расхода (`G_valve`).

## Что делает пользователь

В левой части окна задаёт **известные данные** (значения по умолчанию совпадают
с оригинальным скриптом):

| Группа | Параметры |
|---|---|
| Резервуар и нагрев | V_total (м³), доля заполнения жидкостью, теплоприток Q̇ (Вт), время моделирования t_end (с) |
| Давления | P_init, P_open, P_full (бар) |
| Клапан | диаметр седла d_c (мм), масса золотника m (кг), демпфирование η (Н·с/м), жёсткость пружины c (Н/м), ход ограничителя h_stop (×d_c) |

По кнопке **«РАССЧИТАТЬ»** (расчёт идёт в фоновом потоке, интерфейс не зависает)
в правой части окна строятся графики:

1. **Динамика давления** (бар) с линиями `P_init`, `P_open`, `P_full` — полная
   информативность графика ax1 из оригинала + дополнительная линия `P_full`;
2. **Подъём золотника** (мм) — аналог ax2 оригинала;
3. **Изменение массы газовой части** (кг) + масса жидкой части и полная масса —
   запрошенная пользователем величина, рассчитываемая из `Q` и плотностей
   насыщенных фаз CoolProp;
4. **Массовый расход через клапан** G(t) (кг/с) — величина, непосредственно
   используемая в уравнениях оригинала.

Под графиками — панель навигации matplotlib (zoom/pan/save). Внизу слева —
текстовый отчёт (T нач., преднатяг h₀, P макс, P мин после открытия, сброшенная
масса, макс. подъём). Кнопка **«Сохранить PNG»** сохраняет все графики в файл.

## Структура проекта

```
prv_app/
  engine.py        # вся математика (перенесена 1-в-1 из Another_PRessure_Radau.py)
  app.py           # GUI (PySide6 + matplotlib QtAgg)
main.py            # точка входа для сборки EXE
run_app.bat        # запуск без сборки (нужен установленный Python)
build_exe.bat      # сборка PRV_Calc.exe через PyInstaller (на Windows)
```

## Запуск из исходников

```bat
pip install -r prv_app\requirements.txt
python main.py
```

## Сборка EXE

Запустить `build_exe.bat` на Windows. Результат — `dist\PRV_Calc\PRV_Calc.exe`
(режим `--onedir` выбран потому, что `CoolProp` содержит нативную DLL и плохо
переносится в однофайловый режим; папку `PRV_Calc` нужно переносить целиком).

Примечания:

* Модель двухфазного азота корректна при давлениях ниже критического
  (33.96 бар) — приложение проверяет ввод и предупреждает об этом.
* При очень сильном перегреве системы (полное испарение жидкости и рост T выше
  области применимости HEOS) CoolProp может вернуть экстраполяционные значения —
  это ограничение исходной модели, а не приложения.
