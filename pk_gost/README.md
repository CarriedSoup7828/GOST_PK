# Расчёт предохранительного клапана по ГОСТ 12.2.085-2017

Проектная задача: аварийный теплоприток → аварийный расход Gав → минимальная
площадь седла F → подбор типоразмера, с проверками иерархии давлений.
Среда — азот, сброс из сосуда с жидкой фазой.

## 2. Где менять данные

**Все исходные — в одном месте:** функция `default_case()` в конце
[`pk_gost/inputs.py`](inputs.py). Правьте только её, остальные модули трогать не нужно.

```python
def default_case():
    case = ValveCase(
        fluid='Nitrogen',      # любая среда CoolProp: 'Oxygen', 'Argon', 'Methane'...
        T1=117.5,              # К, температура ПЕРЕД клапаном (абсолютная!)
        Q_heat=20_000.0,       # Вт, аварийный теплоприток
        P_n_g=5.0e5,           # Па ИЗБЫТОЧНЫХ, давление настройки Рн
        P_work_g=3.0e5,        # Рр  рабочее
        P_design_g=6.0e5,      # Р   расчётное
        P_av_max_g=6.6e5,      # Рав max
        P_back_static_g=0.0,   # Рп ст  статическое противодавление
        P_back_dyn_g=0.0,      # Рп дин динамическое противодавление
        dP_in=0.0,             # dPвх потери на входе
        alpha1=0.75,           # коэффициент расхода для газа   \ из ЭД клапана
        alpha2=0.65,           # коэффициент расхода для жидкости/ (п. 5.11)
        N=1,                   # число параллельных клапанов
        balanced=False,        # True — разгруженный (сильфон/поршень)
    )
    case.stubs = {...}         # что помечать в протоколе как ЗАГЛУШКА
    return case
```

### Соглашения по единицам — их легко перепутать

* **Давления — в паскалях и ИЗБЫТОЧНЫЕ** (суффикс `_g` = gauge). 5 бар изб. = `5.0e5`.
  Абсолютные Р1 и Р2 код считает сам по Д.4.2: `Р1 = Рпо + Ратм`.
* **Температура — в кельвинах, абсолютная.** Не в °C.
* **Теплоприток — в ваттах**, не в кВт.
* **Площадь седла `F_mm2` — в мм²**, но она нужна только для поверочной задачи.
  Для проектной оставьте `None`: F считается из Gав по (Д.2).

### Что менять реже

* Каталог типоразмеров — поле `catalog_d0_mm` (диаметры сёдел в мм),
  подбор идёт по правилу 5.5 «равной или ближайшей большей».
* `membrane_device=True` — если стоит мембранно-предохранительное устройство
  (тогда Kc = 0,9 по Д.6).
* `P_po_g` — если изготовитель задал давление полного открытия иначе, чем по 5.4.
* `P_no_g` — если Рно отличается от Рн.

### Несколько вариантов сразу

```python
from pk_gost import inputs, report

for Q in (10_000, 20_000, 50_000):
    case = inputs.default_case()
    case.Q_heat = Q
    r = report.run_case(case)
    print(f'Q={Q:6d} Вт -> Gав={r.load.G_av_kgh:6.1f} кг/ч, '
          f'F={r.sizing.F_required_mm2:6.2f} мм2, d0={r.sizing.d0_selected_mm} мм')
```

## 3. Как проверить, что посчитано верно

Проверка построена на трёх независимых уровнях. **Ни один из них не сверяет
код сам с собой** — везде сравнение с внешними данными.

### Уровень 1. Формулы против справочных данных ГОСТ

`python validate_gost.py` — сверяет с тем, что напечатано в стандарте:

| Эталон | Что проверяет |
|---|---|
| Таблица И.1 | β_кр для 20 реальных сред против (Е.2.4). Совпадение до 0,0014 — это округление таблицы до 3 знаков |
| Рис. Е.2 | β_кр и Кп кр для постоянного показателя изоэнтропы |
| Рис. Е.3, Е.4 | То же для омега-метода + сверка численного решения с аппроксимацией (Е.2.12) |
| Рис. Е.5, Е.6 | Коэффициент Кb |
| Рис. И.1 | Kw: пороги 30 % / 37,7 % / 15 % и значения на краю 50 % |
| Рис. И.3 | Kv по числу Рейнольдса |

### Уровень 2. Интегратор против расчётов разработчиков стандарта

Это главная проверка. Пункт Е.4.1 говорит, что графики Е.9–Е.13 для водяного
пара «**рассчитаны методом прямого интегрирования** по наиболее точным на сегодня
уравнениям... предложенным Международной Ассоциацией по Свойствам Воды и
Водяного Пара (IAPWS)».

То есть авторы ГОСТ прогнали **тот же алгоритм Е.1** на воде и опубликовали
результат. Наш код на воде должен попасть в те же графики — а это сквозная
проверка всей цепочки: построение сетки → плотность на изоэнтропе **в двухфазной
области** → трапеции Е.1.4 → поиск первого максимума → Кп кр.

Результат (`validate_gost.py`, раздел 5):

```
рис. Е.9  (0,1...10 МПа), ось графика 0,58...0,64  ->  получено 0,5826...0,6369
рис. Е.10 (10...22 МПа),  ось графика 0,52...0,62  ->  получено 0,5259...0,6160
```

Плюс рис. Е.11–Е.13 (Z, Tr, ρ_l на линии насыщения) и константы п. Е.4.2
(Ткр = 647,096 К, Rуд = 461,526 Дж/(кг·К)) — совпадают.

**Если вы измените что-то в `integrate.py` и эти проверки поедут — значит
сломали интегратор.** Прогоняйте `validate_gost.py` после любой правки.

### Уровень 3. Против промышленной методики API 520

API 520 Part 1 (источник [6] в библиографии ГОСТ) для критического истечения газа:

```
A = W / (C·Kd·P1·Kb·Kc) · sqrt(T·Z/M),   C = 0,03948·sqrt(k·(2/(k+1))^((k+1)/(k-1)))
```

Подстановка ρ1 = P1·M/(Z·R·T) в (Д.7) показывает, что **формулы алгебраически
тождественны**: `C(API) = 0,03948·Кп кр(ГОСТ)`, `Kd(API) = α(ГОСТ)`, а множитель
3,60/√8314,3 = 0,0394812 — это и есть константа API 0,03948. Проверено численно
для k = 1,0…2,0 с точностью машинного нуля; остаточные 3·10⁻⁵ на сквозном
примере — округление константы в самом API.

Практический смысл: **результат можно предъявлять как совпадающий с
международной практикой**, а не только с ГОСТ.

### Уровень 4. Внутренние контроли в самом протоколе

Их печатает `run_pk.py` при каждом запуске:

* **Контроль Е.1.5** — при критическом режиме должно выполняться
  `G*ideal = sqrt(n·Ркр·ρкр)`. Сейчас сходится до 0,00 %.
  *Исключение:* если Ркр попал на границу фазовой диаграммы, равенство
  заменяется неравенством `sqrt(n⁻·Ркр·ρ) ≤ G* ≤ sqrt(n⁺·Ркр·ρ)` — это
  оговорено в самом Е.1.5 и **не является ошибкой**.
* **Перекрёстная проверка** прямого интегрирования (Е.1) аналитическим методом
  из табл. Д.2. Сейчас 0,13 %. Больше 1–2 % — повод разбираться.
* **Контроль размерных форм** — один и тот же расход, посчитанный четырьмя
  способами: СИ, (Д.7) с константой 3,60, (Д.9) с 1,138 и (Е.1.10) через ρ0
  и интеграл. Расходятся не более чем на 0,04 %.

### С чем сверить дополнительно (вне кода)

* **Каталоги изготовителей** — АО «НПФ ЦКБА» (разработчик стандарта), LESER,
  Broen, Bopp & Reuther. Они публикуют α1, α2, площадь седла F и таблицы
  пропускной способности для конкретных типоразмеров. Подставьте их α и F
  в поверочном режиме (`F_mm2` задан) и сравните G с каталожной таблицей.
  Это единственная проверка, которая захватывает реальный коэффициент расхода.
* **ISO 4126-1** (источник [3]) — метод, к которому ГОСТ заявлен как NEQ.
* Для двухфазных сбросов — **ISO 4126-10** (источник [5]), на нём основан
  омега-метод с учётом неравновесности (Е.5.2).

### Чего расчёт НЕ проверяет

* Коэффициент расхода α берётся из исходных данных — его достоверность
  на совести ЭД клапана (п. 5.11 обязывает изготовителя его указать).
* Динамическое противодавление Рп дин — входной параметр. П. 8.3.1 требует
  определять его гидравлическим расчётом отводящего трубопровода **для всех
  систем**, включая сброс в атмосферу через короткие трубы (Б.1.3).
* Сам сценарий аварии: теплоприток Q задаётся, а не выводится из геометрии
  сосуда и условий пожара/отказа изоляции.

## 5. Важно помнить про азот

Азот — «регулярная» среда (п. 3.1.25, k = 1,40 > 1,1): при изоэнтропном
расширении вблизи насыщения он **конденсируется**. Режим Г-Г реализуется
только при достаточном перегреве — при Рн ≈ 2…25 бар изб. это **примерно
9–10,5 К**. При меньшем перегреве клапан запирается в двухфазной области
(режим Г-2Ф, метод Е.2.3.2), при перегреве ровно на пороге Ркр совпадает
с точкой росы — вырожденный случай Е.1.5.

`run_pk.py` печатает порог автоматически и предупреждает, если запас мал.
Не задавайте Т1 «на глаз» близко к Тнас — результат там чувствителен.

### Ловушка: Ркoнд и Ps(Т1) — разные величины

В таблице чувствительности **Ркoнд падает с ростом температуры**. Это не ошибка.

| | что это | с ростом Т1 |
|---|---|---|
| `Ps(Т1)` | давление насыщения **при температуре Т1** — изотермическое сжатие | **растёт** |
| `Ркoнд` | давление, при котором **изоэнтропа** из (Р1, Т1) пересекает линию конденсации при расширении (п. 3.4, Е.3.3.2) | **падает** |

В расчёте участвует только Ркoнд — оно делит отрезок на интервалы в методе
Е.2.3.2. `Ps(Т1)` выводится рядом исключительно для сравнения.

Механизм: перегрев повышает энтропию s₁, а энтропия сухого насыщенного пара
s_g(P) растёт при **падении** давления (для азота 5018 Дж/(кг·К) при 6,76 бар →
5409 при 1,01 бар). Условие пересечения `s₁ = s_g(Ркoнд)` поэтому выполняется тем
ниже по давлению, чем сильнее перегрет газ — перегретому газу надо расшириться
дальше, чтобы стать насыщенным. Прочерк в колонке означает, что s₁ превысила s_g
даже при Р2: конденсации на отрезке нет вовсе.

То же направление даёт формула самого ГОСТ (Е.3.16):
`Ркoнд = Р1·(Тнас(Р1)/Т1)^(1/(Λg−Λ))` — с ростом Т1 отношение Тнас(Р1)/Т1
убывает, значит убывает и Ркoнд.
